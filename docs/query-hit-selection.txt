命中选择说明：候选命中怎样决定 snippet 与 --show-column 的 column
================================================================

本文只描述现有实现的既有行为，不新增功能。所有结论均可按给出的
“相对路径:行号 / 函数名”与源码逐条核对；涉及的实现文件只有：

  - local_search/search.py        （全部检索逻辑）
  - local_search/__main__.py      （命令行入口）
  - local_search/__init__.py      （公开入口导出）

行号基于当前仓库版本；如源码变动，请以函数名与引用的代码文本为准重新定位。


0. 命令入口与公开入口
----------------------

命令行入口：

    python -m local_search <目录> <关键词> [选项...]

  - local_search/__main__.py:5-6：__main__ 保护块内以
    sys.exit(main(sys.argv[1:])) 启动，main 的返回值即进程退出码。

公开入口：

  - local_search/__init__.py:3 声明 __all__ = ["main"]，
    local_search/__init__.py:5 从 .search 导入 main，
  - 即 local_search.main，定义于 local_search/search.py:619
    （函数 main(argv=None) -> int，local_search/search.py:619-726）。

local_search.main 接受与命令行等价的参数列表（list[str]），返回整数
状态码并向标准输出写入结果；它本身不调用 sys.exit，成功处理完查询
返回 0（local_search/search.py:726），各类失败经 _fail 返回 2
（_fail 定义于 local_search/search.py:86-88：先把消息写入标准错误，
再 return 2）。因此两种入口观察到的命中选择、snippet、column、退出码、
标准输出、标准错误完全一致。对应既有用例：

  tests/test_show_column.py
    ShowColumnTest.test_main_entry_matches_cli
  tests/test_context_chars.py
    ContextCharsTest.test_long_values_via_main_entrypoint_share_behavior


1. 一次查询中命中选择所处的位置
--------------------------------

main（local_search/search.py:619-726）对每个通过路径与格式筛选的文件
调用 _search_file（search.py:276-373，调用点在 677-680），命中选择
全部发生在 _search_file 内部，分两步：

  第一步  行的合格性判定与命中定位：_match_line
          （search.py:232-273）。输入是“检索视图”行文本与对应的
          关键词形式，输出是 (命中位置, 命中词长度) 或 None。
  第二步  片段裁剪与结果项组装：_search_file 的逐行循环
          （search.py:349-372）。按命中位置与 --context-chars 额度
          从源行切出 snippet，按需附加 column，每命中行追加一项。

之后的排序（search.py:707）、--offset / --limit 截取
（search.py:714-717）与序列化（search.py:720-725）只决定哪些结果项
最终输出、以何种格式输出，不再改变任何一项的 snippet 或 column；
column 与 snippet 始终指向同一命中，不随 context_chars、排序或分页
改变。对应既有用例：

  tests/test_show_column.py
    ShowColumnTest.test_column_stable_under_offset_and_limit
    ShowColumnTest.test_column_independent_of_context_chars


2. 关键词匹配：同行内的连续字面子串
------------------------------------

主关键词与 --or-keyword 的替代关键词都按同行内的连续字面子串比较：
不拆词、不解释正则或通配符，关键词首尾的空格保留并参与比较；匹配
不跨行，关键词被拆在两行时任何单行都不命中。判定用 str.find 完成
（_match_line，search.py:259-260）。

  - 每行独立判断：文件按 "\n" 切行（search.py:349），行尾残留的
    "\r" 先剥离（search.py:350），判定与片段都只覆盖当前行，不借用
    相邻行。
  - 对应既有用例：

3. 两词均有命中时选哪一次：起点最靠左，同起点选主词
----------------------------------------------------

_match_line（search.py:259-268）的选择规则：

  - 主关键词与替代关键词各自取行内最左侧的一次出现（str.find 的
    返回值即最左起点）；
  - 两词都有命中时，选择起点最靠左的一次（search.py:263-268）；
  - 起点相同（含两词相同或前缀重叠，如主词 abc 与替代词 ab 同起于
    同一位置）时选主关键词（search.py:263-264 的 <= 比较）；
  - 片段长度由所选词决定：返回的长度是 len(所选关键词)
    （search.py:266、266），命中替代词时片段围绕替代词、长度按
    替代词计算；
  - 未提供 --or-keyword 时只按主关键词判定，即围绕主关键词最左侧
    命中，与既有行为一致。

4. 每文件返回哪些行：默认首个合格行，--all-lines 逐行
------------------------------------------------------

  - 默认（不加 --all-lines）：每个文件只返回首个合格行。_search_file
    在收集到首个命中后立即 break（search.py:371-372），同文件后续
    合格行不再产生结果项。
  - --all-lines：每个合格行各返回一项，按行号递增排列
    （search.py:349-372 的逐行循环不中断）。
  - 同一行关键词重复出现仍只有一项：_match_line 每行至多返回一个
    (位置, 长度)，每行至多向结果追加一项（search.py:363-370），
    片段以该行最左侧命中为中心；两词都出现或各自重复出现都不增加
    项数。

5. --ignore-case：仅折叠 ASCII 字母，片段保留源文大小写
--------------------------------------------------------

  - 折叠规则：仅把 ASCII 的 A-Z 映射为 a-z（_ASCII_UPPER_TO_LOWER，
    search.py:63-65；_ascii_lower，search.py:99-101），按码点一一
    映射，不产生多字符展开（ß 不会变成 ss），也不影响 É 等非 ASCII
    字符。
  - 折叠只用于定位：开启 --ignore-case 时，关键词与行文本先各自
    折叠再交给 _match_line（search.py:336-347、346）；片段始终从
    源行切取（search.py:365 的 line[start:end] 用的是未折叠的
    line），保留源文大小写。
  - 折叠按码点一一映射、不改变词长，因此命中位置与列号对源文本与
    检索视图一致（search.py:239-245、324-327 的 docstring 说明）。

6. 片段裁剪：只取当前行，默认前后各 30 个码点，0 时仅保留命中词
----------------------------------------------------------------

裁剪在 _search_file 的逐行循环内完成（search.py:361-362）：

    start = max(0, position - context_chars)
    end = min(len(line), position + hit_length + context_chars)

  - 上下文只取当前行：到行首或行尾停止，不借用相邻行，不添加省略号，
    片段不含换行符；
  - 默认前后各 30 个 Unicode 码点（DEFAULT_CONTEXT_CHARS = 30，
    search.py:27），按码点计：中文与补充平面字符（如 😀）各算一个，
    关键词自身长度不计入额度；
  - --context-chars 0 时 start == position、end == position +
    hit_length，片段只保留完整命中词；
  - 行内可用上下文不足额度时只保留该行实际存在的内容，不补齐。

7. column：从 1 开始按源行码点计数
-----------------------------------

--show-column 开启时，每项额外携带整数 column（search.py:367-369）：

    hit["column"] = position + 1

  - position 是命中起点在源行内的码点下标（从 0 起），列号从 1 起；
  - 按源文件行的 Unicode 码点计数：中文、补充平面字符（如 😀）与
    制表符各算一码点，组合字符（如 e + 组合重音符）按实际码点数
    累计；
  - 与片段裁剪无关：列号取自裁剪前的 position，不随
    --context-chars 改变；也与 UTF-8 字节数、终端显示宽度无关；
  - column 与 snippet 始终指向同一命中（第 3 节选出的那一次），
    不随排序或 --offset / --limit 改变；
  - 未开启 --show-column 时结果项没有 column 字段，输出与既有格式
    完全一致（结果项组装在 search.py:700-704，仅 show_column 为真
    时附加 "column" 键）。

对应既有用例：

8. --and-keyword 与 --not-keyword：只决定行是否合格
----------------------------------------------------

附加词与排除词只判断整行是否合格，不改变所选命中的位置：

  - --and-keyword：可重复指定，同一行还须包含全部附加关键词中的每一个
    才算命中（_match_line，search.py:269-270），各词位置不限，可与
    主关键词的命中或彼此之间重叠、共用文字；某个附加词只在其他行出现
    不能合并，附加词的指定顺序与重复值不影响判定；片段仍只围绕主
    关键词（或按第 3 节选出的词）的最左命中，不为展示任何附加词扩大
    片段；
  - --not-keyword：完整当前行内任何位置出现排除关键词（包括片段
    之外）即排除该行（search.py:271-272）；排除词在其他行出现不
    影响本行；排除只影响行的合格性，不改变片段的取法；
  - 各词都按连续字面子串匹配，--ignore-case 同时作用于主词、全部
    附加词与排除词，仍只折叠 ASCII 字母（search.py:337-344）。

9. 固定资料演示：两词竞争时的 snippet 与 column
------------------------------------------------

演示目录中只有一个 UTF-8 文件 a.txt，两行原文如下，均以 LF 结束：

  第 1 行：前😀TAR xx TARGET
  第 2 行：中Target TAR

第一次查询（默认模式）：

    python -m local_search <演示目录> target --or-keyword tar \
        --ignore-case --context-chars 0 --show-column

  命中选择过程：

  - 第 1 行折叠后为 “前😀tar xx target”。主关键词 target 的最左
    起点在码点下标 9（行尾 TARGET 处），替代关键词 tar 的最左起点
    在码点下标 2（TAR 处）。起点 2 更靠左，选替代词的一次命中，
    长度按 tar 计为 3（第 3 节规则）。--context-chars 0 使片段只
    保留完整命中词，snippet 为源行 [2:5] 的 “TAR”（保留源文大
    小写）；column = 2 + 1 = 3（前 算 1 码点、😀 算 1 码点，T 是
    第 3 码点）。
  - 默认模式每文件只返回首个合格行，a.txt 在第 1 行命中后即停止
    （search.py:371-372），第 2 行不产生结果项。

  预期：
    退出码：0
    标准输出（JSON，末尾一个换行）：
      [{"path": "a.txt", "line": 1, "snippet": "TAR", "column": 3}]
    标准错误：空

第二次查询（仅追加 --all-lines）：

    python -m local_search <演示目录> target --or-keyword tar \
        --ignore-case --context-chars 0 --show-column --all-lines

  逐行模式下第 2 行也产生结果项。第 2 行折叠后为 “中target tar”：
  主关键词 target 与替代关键词 tar 的最左起点同在码点下标 1
  （target 以 tar 开头，前缀重叠），起点相同选主关键词，长度按
  target 计为 6；snippet 为源行 [1:7] 的 “Target”，
  column = 1 + 1 = 2。两项按行号递增排列（search.py:707 的排序
  键 (path, line)，同一路径按行号升序）。

  预期：
    退出码：0
    标准输出（JSON，末尾一个换行）：
      [{"path": "a.txt", "line": 1, "snippet": "TAR", "column": 3}, {"path": "a.txt", "line": 2, "snippet": "Target", "column": 2}]
    标准错误：空

两次查询的命令行只差一个 --all-lines：差异全部来自“每文件返回
哪些行”的规则（第 4 节）；每一行内部选哪次命中、snippet 与
column 的取值规则（第 3、6、7 节）在两种模式下完全相同。

对应既有用例（演示布局与断言方式相同）：

  tests/test_show_column.py
    ShowColumnTest.test_demo_scenario_json_columns
    ShowColumnTest.test_demo_scenario_option_order_invariance
  tests/test_or_keyword.py
    OrKeywordTest.test_acceptance_default_returns_earliest_qualified_line
    OrKeywordTest.test_acceptance_all_lines_returns_each_qualified_line


10. 边界与错误行为
------------------

  - 未开启 --show-column：JSON 每项只有 path、line、snippet 三个
    字段，没有 column 字段（search.py:700-704 仅在 show_column 为
    真时附加该键）。对应既有用例：
      tests/test_show_column.py

      tests/test_or_keyword.py

  - 无命中：输出空数组 [] 加一个换行（json.dumps，search.py:723），
    退出码仍为 0，标准错误为空；这不是错误。对应既有用例：
      tests/test_show_column.py
        ShowColumnTest.test_no_hit_outputs_empty_results

        OrKeywordTest.test_no_match_returns_empty_json_array
      tests/test_first_hit_snippet.py
        FirstHitSnippetTest.test_no_occurrence_anywhere_returns_empty_array

  - 重复指定 --show-column：在目录扫描开始之前由参数解析阶段报错
    （_parse_args 的去重检查，search.py:587-588），经 _fail 返回 2：
    退出码 2，标准输出完全为空（结果输出在 search.py:724-725，所有
    出错路径都在其之前 return），标准错误为一行
    “错误: 选项 --show-column 只能指定一次”，包含该选项名与
    “只能指定一次”。对应既有用例：
      tests/test_show_column.py

  - 源文件始终只读：整个流程只对候选文件做一次只读打开
    （search.py:334），结果只写入标准输出（search.py:724-725），
    查询不生成索引或导出文件，目录内容在查询前后不变。对应既有用例：
      tests/test_or_keyword.py
        OrKeywordTest.test_query_is_read_only_and_leaves_no_index
      tests/test_show_column.py
        ShowColumnTest.test_demo_scenario_json_columns（查询前后快照一致）
